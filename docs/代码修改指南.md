## 0. 动手前必须知道的四条约束

这个仓库带有很强的"源码身份校验"机制。不了解这些机制就直接改代码，测试或采样会直接拒绝运行。

1. **`training_wavestitch.py` 受白名单约束。**
   - 它必须**逐字节**等于"上游原文件 + `scripts/verify_upstream_boundary.py` 中登记的编辑列表"。
   - 测试 `test_training_reporting.py` 和 `test_training_input_dropout.py` 会核对这一点。
   - 所以任何改动都要做到两件事：在 `verify_upstream_boundary.py` 里新增一组 `*_EDITS`，并在 `expected_training_source()` 中应用这组编辑。直接改文件，测试一定会失败。
2. **训练监控器按代码文本定位行号。**
   - `scripts/run_simulation.py` 通过逐行匹配文本来找两行代码：`optimizer.step()` 和 `for epoch in range(args.epochs):`。
   - 它还会读取局部变量 `loss`、`loss_weight`、`batch`。
   - 因此这两行代码的文本不能改，这三个变量名也不能改。
3. **改动以下两个文件，会导致旧 checkpoint 不能在仓库根目录下采样。**
   - 采样前会比对 `TSImputers/S4Model.py` 和 `signal_normalization.py` 的 sha256 与训练时的记录，不一致就拒绝运行。
   - 除非你接受"旧模型只能从各自冻结的 workspace 里采样"，否则**不要改这两个文件**。
4. **新增模块要在 5 处登记。** 新的 `.py` 文件必须加入以下源码清单，否则不会被复制进冻结的 workspace，也不会进入运行记录：
   - `scripts/run_dreamt.py:66`
   - `scripts/run_all88_s092_sweep.py:44`
   - `scripts/compare_s092_sweep_best.py:33`
   - `scripts/run_simulation.py:107`
   - `scripts/verify_upstream_boundary.py`

**默认值原则**（沿用项目已有的惯例）：新功能一律通过配置开启，默认关闭；关闭时的行为必须和旧版本**逐位一致**，不能多消耗任何随机数。

## 2. P0-1　整夜生成保存时必然失败

### 现象和证据
- `night_data.save_night_npz` 规定 `generated < 0` 直接报错（代码注释写明"不做裁剪"）。
- 但当前模型会产生负值：3 个窗口共 9000 个点中有 **199 个负值**，最小 −0.085 秒。
- 整夜有 667,500 个点，按这个比例几乎不可能一个负值都没有。所以 GPU 跑完整夜后，只会留下 `diagnostic_generated.npz` 然后报错，正式输出 `S092.npz` 永远写不出来。

### 根源
- 当前配置是 `missing_value_policy: "preserve"`，训练目标里包含原始数据中表示缺失的 0，模型因此学会了生成"缺失标记"。
- 数据可以印证这一点：

| | 数量 |
|---|---|
| 真实数据里的缺失标记 0 | 461 |
| 生成值小于 0.2 秒 | 497（其中 199 个是负值） |
| 生成值在 0.2–0.35 秒之间 | 几乎没有 |
| 真实 IBI 的最小正值 | 0.35 秒 |

- 也就是说，0 附近那一簇生成值整体都是"缺失标记"，**不只是负值部分**。
- 如果只把负值截成 0，还会留下大约 300 个 0–0.1 秒的假心搏。

### 修复 A（根治）
改用 `masked` 策略并重新训练，见第 4 节。

### 修复 B（兜底，不需要重训）：按阈值把这簇值写成缺失标记，作为显式开关

`night_data.py`：

```python
# 一个正常的成年人在睡眠中，IBI 不会低于 0.3 秒（相当于心率超过 200 bpm）。
# 低于阈值的生成值，视为模型在模仿 DREAMT 数据中的缺失标记 0。
MAX_MISSING_THRESHOLD_SECONDS = 0.3


def save_night_npz(path, prepared, generated_seconds, *, missing_threshold_seconds=None):
    ...  # 后缀、形状、dtype 的检查保持不变
    if not np.isfinite(generated).all():
        raise ValueError("Generated IBI must be finite and nonnegative; values are not clipped")
    negative = int((generated < 0).sum())
    marker = np.zeros(generated.shape, dtype=bool)
    if missing_threshold_seconds is None:
        # 旧行为：错误信息逐字保留，现有测试会用正则匹配它
        if negative:
            raise ValueError("Generated IBI must be finite and nonnegative; values are not clipped")
    else:
        threshold = float(missing_threshold_seconds)
        if not 0.0 < threshold <= MAX_MISSING_THRESHOLD_SECONDS:
            raise ValueError("missing_threshold_seconds must lie in (0, 0.3] seconds")
        marker = generated < threshold
        generated = np.where(marker, 0.0, generated)
    ...  # 后续 float32 转换和写文件逻辑不变
    return dict(...,  # 原有字段
                missing_threshold_seconds=missing_threshold_seconds,
                generated_negative_samples=negative,
                written_as_missing_samples=int(marker.sum()))
```

`scripts/generate_night.py`：

```python
parser.add_argument("--missing-threshold-seconds", type=float, default=None,
                    help="Write generated IBI below this value as the DREAMT missing marker 0 "
                         "(default: off, any negative value is an error)")
...
report["output_npz"] = save_night_npz(output_path, prepared, generated,
                                      missing_threshold_seconds=cli.missing_threshold_seconds)
...
# 注意：这里原来写死了 invalid_values_clipped_or_repaired=False，开启阈值后必须如实记录
report.update(invalid_values_clipped_or_repaired=cli.missing_threshold_seconds is not None)
```

**测试**（`tests/test_night_data.py`、`tests/test_generate_night.py`）：
- 不传阈值时遇到负值仍然报错，现有用例不改。
- 阈值设为 0.2 时：小于 0.2 的值写成 0，计数正确；大于等于 0.2 的值逐位不变。
- 阈值为 0 或大于 0.3 时会被拒绝。

**验收**：整夜输出的 `zero_samples` 与真实记录里的缺失数量在同一个量级。

## 3. P0-2　验证 KL 逐轮剧烈震荡：加入 EMA，并保存每一轮的 checkpoint

### 现象（已用 config_1 的 `epoch_metrics.csv` 确认）

| | 数值 |
|---|---|
| 训练 loss | 0.0656 → 0.0385，平稳下降 |
| 验证 KL 范围 | 0.78–111，中位数 16.7 |
| KL 与 epoch 的秩相关 | 0.20（p = 0.17），没有显著趋势 |
| 相邻两轮 log KL 的自相关 | 0.16，几乎彼此独立 |
| 相邻两轮 KL 之比的中位数 | 约 2.1 倍 |
| KL < 2 的 epoch | 只有 13、14、25、38 这 4 轮 |
| 被选中的第 25 轮 | KL 0.78，但前后两轮分别是 16.1 和 8.1 |

**结论：这不是后期退化，而是从第 7 轮起就持续的逐轮震荡。**
- 每轮验证用的是同一个 seed，所以这种波动来自权重本身的变化（每个 epoch 有 8628 步更新），而不是采样时的随机性。
- loss 平稳下降、样本质量却剧烈抖动，这是 DDPM 类模型不做权重 EMA（指数滑动平均）时的典型表现。因此 EMA 是首选的修复。
- 第 25 轮是一个偶然的低谷，用它生成的结果不代表这个模型的典型水平。

还有一个需要排除的因素：KL(真实‖生成) 在生成方差偏小时会急剧放大，所以 KL 的长尾也可能部分来自指标本身过于敏感。`validation/epoch_NNNN/` 下保存了每个窗口的 `kl_mean_term` 和 `kl_variance_term`，对比几个高 KL 的 epoch（例如第 7、10 轮）和低 KL 的 epoch（例如第 13、25 轮），就能看出是均值偏移还是方差塌缩。

### 3.1 新增 `training_ema.py`

```python
"""Opt-in EMA of model parameters for validation and checkpoints only.

decay=0 (default) creates no copy and changes no random stream, so legacy
runs stay bitwise identical. Buffers are copied, never averaged.
"""
from __future__ import annotations

import copy
import json
import math
import os
from numbers import Real
from pathlib import Path

import torch


def ema_options(config):
    configured = config.get("training_ema", {})
    if not isinstance(configured, dict) or set(configured) - {"decay"}:
        raise ValueError("training_ema accepts only decay")
    decay = configured.get("decay", 0.0)
    if (isinstance(decay, bool) or not isinstance(decay, Real)
            or not math.isfinite(decay) or not 0.0 <= decay < 1.0):
        raise ValueError("training_ema.decay must be finite and within [0, 1)")
    return dict(decay=float(decay))


class TrainingEMA:
    def __init__(self, model, decay):
        self.decay, self.updates, self.model = float(decay), 0, None
        if self.decay == 0.0:
            return
        self.model = copy.deepcopy(model)
        self.model.requires_grad_(False)

    @torch.no_grad()
    def update(self, model):
        if self.model is None:
            return
        self.updates += 1
        decay = min(self.decay, (1 + self.updates) / (10 + self.updates))  # 早期预热
        for ema_param, param in zip(self.model.parameters(), model.parameters()):
            ema_param.lerp_(param.detach(), 1.0 - decay)
        for ema_buffer, buffer in zip(self.model.buffers(), model.buffers()):
            ema_buffer.copy_(buffer)

    def evaluation_model(self, model):
        return model if self.model is None else self.model

    def report(self):
        return dict(decay=self.decay, active=self.model is not None, updates=self.updates,
                    warmup="min(decay, (1+n)/(10+n))", buffers="copied from the training model")


def create_training_ema(model):
    """Read the same selected JSON as Preprocessor; no independent overrides."""
    selected = os.environ.get("DREAMT_CONFIG_PATH")
    path = (Path(selected).expanduser().resolve() if selected
            else Path(__file__).resolve().with_name("dataset_config.json"))
    config = json.loads(path.read_text(encoding="utf-8-sig")) if path.is_file() else {}
    return TrainingEMA(model, ema_options(config)["decay"])
```

**为什么这样可以直接接入**：
- 验证器 `EpochValidator.run(epoch, training_model, ...)` 不检查传入的是不是同一个模型对象，只读取 `state_dict()`。
- EMA 模型是训练模型的 deepcopy，参数名完全相同，缓冲区也逐位相同，所以 `load_original_parameters` 的缓冲区一致性校验能够通过。
- 下游所有用 `load_state_dict(strict=True)` 加载 checkpoint 的采样脚本也都兼容。

- 会执行真实训练循环的测试（`test_training_input_dropout.py`、`test_training_reporting.py`）需要在命名空间里注入 `training_ema=TrainingEMA(model, 0.)`。

- `scripts/run_simulation.py` 要把 `training_ema.py` 加进源码清单，并把 `training_state['training_ema'].report()` 写入运行记录。

## 4. P1-3　缺失值策略：从 `preserve` 改为 `masked`

`dataset_config.json`：

```json
"missing_value_policy": "masked",
```

也可以用命令行参数：`python scripts/run_dreamt.py --missing-value-policy masked`。仓库里已有 `scripts/run_missing_value_ablation.py`，可以直接用它对比三种策略。

| 策略 | 训练目标 | 生成结果 | 评价 |
|---|---|---|---|
| `preserve`（当前） | 包含缺失标记 0 | 会生成约 5% 接近 0 的值，其中一部分是负值 | 和 `observed_only` 评估矛盾，也导致问题 1 |
| `masked`（推荐） | 只在 IBI > 0 的位置计算 loss | 不会学习生成缺失标记 | 训练和评估口径一致 |
| `zero_fill_one` | 把缺失值填成 1.0 秒 | 会学会生成 1.0 秒的假平台 | 不推荐 |

**注意**：
- 改成 `masked` 后，整夜输出将不再包含缺失标记。如果下游（例如 WatchSleepNet 的训练）需要真实的缺失比例，应该单独加一个后处理步骤去插入缺失，不要再让扩散模型去学。
- 这一项和第 3 节的 EMA 放在**同一次重训**里做：先做一组 `masked + EMA`，再与 `preserve + EMA` 对比。

## 5. P1-4　选模型：用多个 seed 复评候选 epoch

### 问题
- 每一轮验证都用同一个 seed（20261020），每个窗口只生成一次。
- 从 50 个这样带噪声的 KL 里取最小值，选中的可能只是"恰好和这组噪声配合得好"的 epoch。

### 做法（依赖第 3.4 节保存的逐轮 checkpoint）

1. 候选 epoch：验证 KL 最低的 5 个 epoch，再加上最后一个 epoch。
2. 每个候选 epoch 用 5 个与训练验证不同的 seed，在**全部验证窗口**上各采样一次。
3. 汇报每个候选的 KL 均值 ± 标准差，选均值最低的。如果前几名之间的差距小于一个标准差，就选较早的 epoch，或者直接选 EMA 权重。

**实现上最省事的办法**：
- 给 `scripts/compare_s092_sweep_best.py` 加一个参数 `--checkpoint-epoch N`，让它读取 `validation/epoch_NNNN/model.pth`，而不是只读最优快照。
- 冻结源码、`--all-windows --window-stride-seconds 120` 全窗口采样、配对指标这些已有流程都可以复用。

### 比较不同配置时，也不要用 KL 最小值（来自 sweep 数据）
- 9 组配置的 KL 最小值全都落在 0.52–0.81 之间，彼此几乎没有区别。这些最小值反映的是逐轮震荡中偶然出现的低谷，而不是配置本身的好坏。
- 改用**最后 10 个 epoch 的 KL 中位数**（再配合多个 seed）来比较配置，配置之间相差 10 倍，区分度清楚得多：

| 配置 | 第 41–50 轮 KL 中位数 | 与 epoch 的秩相关 |
|---|---|---|
| 4：m11 / S4 dropout p=0.03 | **3.2** | −0.55（p < 0.001，持续下降） |
| 5：m11 / S4 dropout p=0.05 | **3.1** | −0.51（p < 0.001，持续下降） |
| 6：01 / 无 dropout | 5.5 | −0.46（p = 0.001） |
| 8：01 / 输入 dropout p=0.05 | 5.9 | −0.13（不显著） |
| 0 / 3：m11 / 无 dropout | 25.2 | −0.01（不显著） |
| 1：m11 / 输入 dropout p=0.03 | 28.9 | +0.20（不显著） |
| 2：m11 / 输入 dropout p=0.05 | 30.8 | +0.31（p = 0.03，上升） |
| 7：01 / 输入 dropout p=0.03 | 34.2 | +0.34（p = 0.02，上升） |

- 注意：每个配置只训练了一次，所以这张表只能说明方向，不能当作定论。
- S4 dropout 的两组在第 50 轮时 KL 仍在下降，说明还没训练充分。下一轮可以延长到 100 个 epoch，并加上 EMA。
- 配置 9–11（minmax [0,1] + S4 dropout）的数据这次没有拿到；从上表的趋势看，它们最值得补齐。

## 5b. P1　输入 dropout：被擦除的点贡献了 81–92% 的训练 loss

### 证据（来自 sweep 数据）
- 被擦除的位置上，模型看不到 x_t，而训练目标 ε 是逐点独立的噪声，从相邻点也推断不出来。所以这些位置的最优预测只能是 0，单点 loss 的期望约等于 1。
- 由此推出，最终训练 loss 应该约等于 `base + p·(1 − base)`，其中 base 是不加 dropout 时的 loss。
- 4 组实测值与这个理论值的误差都在 3% 以内：

| 归一化范围 | p | 无 dropout 时的 loss | 实测 loss | 理论值 | 被擦除点占总 loss 的比例 |
|---|---|---|---|---|---|
| [−1, 1] | 0.03 | 0.0077 | 0.0385 | 0.0375 | 81% |
| [−1, 1] | 0.05 | 0.0077 | 0.0584 | 0.0573 | 87% |
| [0, 1] | 0.03 | 0.0049 | 0.0354 | 0.0348 | 86% |
| [0, 1] | 0.05 | 0.0049 | 0.0553 | 0.0547 | 92% |

- 也就是说，开启输入 dropout 后，绝大部分梯度来自根本学不到的目标。这和上一节的结果一致：输入 dropout 的 4 组配置中，有 3 组的后期 KL 最差，而且有 2 组 KL 随训练显著上升。

### 修改建议
1. **首选**：停用输入 dropout（概率设为 0），改用 S4 dropout。S4 dropout 不会改变训练目标，sweep 数据也支持它。
2. **如果仍想保留输入 dropout**：把被擦除的位置排除在 loss 之外。
   - 让 `TrainingInputDropout.__call__` 同时返回被擦除位置的掩码 `dropped`（形状 `[B, L]`）。
   - 在训练循环中用 `masked_noise_mse(sigmas_predicted, sigmas_permuted, keep)` 计算 loss，其中 `keep = ~dropped`；在 masked 策略下还要再与观测掩码取交集，即 `keep = observed_mask & ~dropped`。
   - 这要求修改 `training_wavestitch.py`，必须走白名单编辑。同时要更新 `training_input_dropout.py` 运行报告中的 `loss_changed` 和 `epsilon_targets_changed` 两个字段，如实记录这一变化。
   - 修改后，训练 loss 应该回到与无 dropout 时相同的量级（约 0.005–0.008）。

## 6. P1-5　指标：补上 IBI 的阶梯结构

### 关键发现（S092 的 3 个窗口实测）

25 Hz 采样下的真实 IBI 是**阶梯状信号**：每个心搏间期的值保持一段时间不变，保持的时长约等于这个值本身。生成序列则是一条连续抖动的曲线。高斯 KL 只比较均值和方差，完全看不出这种差别。

| 指标 | 真实 | 生成 |
|---|---|---|
| 相邻采样点相等的比例 | 0.973–0.975 | 0.000–0.001 |
| 每个窗口的平台数 | 75–81 | 约 3000（相当于没有平台） |
| 平台时长中位数 | 1.72–1.76 秒 | 0.04 秒（即单个采样点） |
| 平台时长与平台取值之差的中位数 | 0.01 秒 | 1.6–1.7 秒 |
| Wasserstein-1（窗口 0 / 1 / 2） | — | 222 / 71 / 137 ms |

其中窗口 1 的 KL 只有 0.001，但 Wasserstein 距离仍有 71 ms。这说明只看 KL 会严重高估生成质量。

### 6.1 新增 `ibi_structure_metrics.py`（只用 numpy，已在上述数据上跑通）

```python
import numpy as np


def step_structure(x, fs=25, tol=1e-6):
    """Plateau diagnostics for 25 Hz sample-and-hold IBI (seconds)."""
    x = np.asarray(x, dtype=np.float64)
    d = np.abs(np.diff(x))
    edges = np.flatnonzero(d > tol) + 1
    bounds = np.concatenate(([0], edges, [len(x)]))
    seconds = np.diff(bounds) / fs
    values = x[bounds[:-1]]
    inner_s, inner_v = seconds[1:-1], values[1:-1]   # 首尾平台被窗口截断，不参与计算
    keep = inner_v > 0
    mismatch = float(np.median(np.abs(inner_s[keep] - inner_v[keep]))) if keep.any() else float("nan")
    return dict(hold_fraction=float((d <= tol).mean()), plateaus=int(len(values)),
                median_plateau_seconds=float(np.median(seconds)),
                median_abs_duration_minus_value_seconds=mismatch)


def w1_paired(reference, generated, observed):
    """Wasserstein-1 on the same observed positions (equal counts -> sorted difference)."""
    r = np.sort(np.asarray(reference)[observed])
    g = np.sort(np.asarray(generated)[observed])
    return float(np.mean(np.abs(r - g)))
```

### 6.2 接入方式
- 在 `EpochValidator._generate` 的诊断信息（`metrics["diagnostics"]`）里，按窗口计算这些指标并写入 `epoch_metrics.csv`。
- 计算前先把数据从 GPU 拷到 CPU，每轮只有几个窗口，开销可以忽略。
- 这些指标先只做诊断，**不参与选模型**。观察两三次重训之后，再决定是否把 Wasserstein 距离加入选模型的标准。

### 6.3 可选后处理：转成阶梯状的心搏序列

这一步作为显式开关，输出单独的文件，不替换原始生成结果：

```python
def to_sample_and_hold(generated, fs=25, missing_threshold=0.2):
    """Each beat value is held for its own duration; values below threshold become marker 0."""
    g = np.asarray(generated, dtype=np.float64)
    out = np.empty_like(g)
    i = 0
    while i < len(g):
        v = g[i]
        if v < missing_threshold:
            out[i] = 0.0
            i += 1
            continue
        n = max(1, int(round(v * fs)))
        out[i:i + n] = v
        i += n
    return out
```

- 实测效果：处理后相邻点相等的比例为 0.970–0.975，平台时长与取值之差约 0.01 秒，结构与真实数据一致。
- 缺失标记的数量也接近：生成 145 / 129 / 77 个，真实 143 / 176 / 142 个。
- 但它**不能修复**模型在分布层面的偏差，窗口 0 的 Wasserstein 距离仍有 189 ms。
- 从长期看，更根本的方向是改为**在心搏层面建模**：先生成心搏间期序列，再展开到 25 Hz。

## 9. 已核实正确、请不要"修"的部分

- **S4 Cauchy 慢速路径补上共轭项**：做过数值验证，修正后与 pykeops 公式的差异在 1e-15 量级，原版差 13.8。改法与 state-spaces 官方的 `cauchy_naive(conj=True)` 一致。

- **采样噪声项改为乘后验标准差**（`sqrt(β̃_t)`），反向一步的均值公式也正确。
