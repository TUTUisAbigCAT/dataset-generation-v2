## 1. 结论

1. **评估方式有问题。**
   - 只评估 S092 一个人，而且 S092 本身比较特殊。
   - 挑 checkpoint 用的指标 KL 看不出分布形状。
2. **训练的问题是不稳定，不是训练量不够。** 相邻 epoch 之间 KL 能从 0.4 跳到 300 以上；43 万次参数更新已经和同类文献处在同一量级。
3. **模型本身的不足**：
   - 生成的不是阶梯状序列。
   - 0.9 s 和 1.8 s 两个峰之间被填平。
   - 睡眠阶段条件几乎不起作用。
   - 模型偏小：4 层、64 通道。

## 2. 诊断

### 数据（既定条件，不做修改）

下面这些是数据本身的特性，模型要学会照原样生成：

- **两个峰**：S092 有 66% 的 IBI 值在 1.6–2.0 s，30% 在 0.6–1.2 s，两者之间会突然跳变。生成结果也应该重现这种双峰和跳变。
- **边界缺失 0**：每个 30 秒段的第 1 秒有 79% 是 0，最后 1 秒有 60% 是 0。训练沿用 `preserve` 策略（把 0 当作数据的一部分）。生成整晚数据时，用 `--missing-threshold-seconds` 把接近 0 的值标成缺失，不改原始数据。
- **时间连续性无法核对**（`source_time_continuity_verified: false`），作为已知限制记录在报告里。

### 评估
- **只看一个受试者**：挑 checkpoint 和评估都只用 S092，看不出问题是 S092 特有的还是普遍存在。
- **早期的 3 窗口结果碰巧好**：KL 0.077 这个水平，在整晚所有可比的片段里只有 4% 能达到，典型水平（中位数）是 0.57。
- **KL 的盲点**：
  - 只比较均值和方差：一个均值、方差都对的单峰分布，W1 也有 172 ms。
  - 窗口内打乱顺序结果不变，看不出时间结构。
  - 平均值被少数窗口拉高。
  - 模型看不到真实 IBI，逐窗口一对一比较本来就做不到（生成与真实的窗口均值相关系数只有 −0.03）。

### 训练
- **KL 剧烈震荡**：不同 config 的 KL 在同样几个 epoch 一起冲高，说明震荡主要来自共用的训练过程，而不是配置本身。
- **loss 仍在缓慢下降**：最后阶段每 10 个 epoch 降约 2%。学习率全程不变，没有梯度裁剪。

### 生成结果
- **阶梯结构**：相邻采样点完全相等的比例，真实 97%，生成 0%。
- **两峰之间**：1.2–1.6 s 的占比，真实 2.8%，生成 15–24%（config 10 为 7%）。
- **睡眠阶段**：Deep 阶段平均 IBI，真实 1.42 s（四种阶段中最低），生成 1.56 s（最高）。
- **边界掉到 0**：`preserve` 策略把缺失 0 当成数据的一部分训练，所以生成结果也会在边界掉到 0（config 8 生成值中 4.6% 小于等于 0）。这和原始数据的格式一致，由生成时的缺失阈值处理。

### 配置比较（要点）

| | 最佳 | 说明 |
|---|---|---|
| 整晚平均 KL | config 8：0.560 | [0,1] 归一化 + 输入 dropout 0.05 |
| 222 个窗口的 W1 / KS | config 10：46 ms / 0.098 | [0,1] 归一化 + S4 dropout 0.03；来自训练时的验证结果 |
| 训练后期稳定性 | config 11：最后 10 个 epoch 中位 KL 1.84 | S4 dropout 那一组整体最稳（4 个 S4 dropout 配置包揽前四，两种归一化都是如此） |

归一化：在 dropout 设置相同的配对中，[0,1] 在 KL 上多数占优，但在 W1 上多数不占优，所以证据不一致。

参照值：真实与真实相比，W1 11 ms、KS 0.019。

### 条件有效性验证的做法

目的：判断睡眠阶段和人口学信息（AHI、BMI、年龄、性别）这些条件，是否足以引导生成。所有检查都用同一个冻结的 checkpoint，只改变输入的条件，其余全部固定。

1. **真实数据里条件能解释多少（上限）**：在 88 个受试者的真实数据上，统计窗口平均 IBI 有多大比例的差异可以由睡眠阶段和人口学信息解释（例如回归的 R²），并分别给出各阶段的 IBI 分布。如果真实数据里条件本身就解释不了多少，生成也不可能被它们有效引导。
2. **换睡眠阶段**：同一组窗口，分别把阶段条件全部设成 W、Light、REM、Deep 各生成一次，比较四组生成结果之间的差异：
   - 各阶段平均 IBI 的排序，是否和真实数据一致。
   - 阶段之间的差异幅度（例如 Deep 与 Light 的均值差、W1），是否接近真实数据。
3. **打乱条件**：把窗口之间的阶段条件随机打乱后再生成，与用正确条件生成的结果比较"按真实阶段对齐的 W1"（把每个位置按它真实的睡眠阶段分组，分别算 W1 再加权平均）。如果两者差不多，说明模型基本没在用阶段条件。
   注意不能用合并 W1：打乱只是交换了窗口之间的阶段序列，整体的阶段构成不变，合并 W1 看不出差别。
4. **换人口学信息**：在 S092 和几个典型受试者之间互换 AHI、BMI、年龄、性别，再生成，得到"生成（用 i 的条件）对真实（j）"的距离矩阵（W1）。如果对角线（用自己的条件）的距离最小，说明人口学条件能把人区分开；否则说明这些条件不足以引导到具体的人。

**判定建议**（阈值可再讨论）：
- 阶段排序与真实一致，且阶段间差异达到真实的一半以上。
- 打乱条件后，按真实阶段对齐的 W1 比正确条件下变差 20% 以上。
- 换人口学信息时，多数受试者的对角线距离最小。

全部满足，可以认为条件足以引导生成；否则就是条件不足，需要先解决这个问题，再谈其他优化。

## 5. 实验计划

1. **阶段 0（不训练）**：
   - 用 **任意受试者评估脚本**（`scripts/evaluate_subject_windows.py`），在 S092 和 4 个典型受试者上评估 config 4 和 5。如果典型受试者明显好于 S092，问题主要在 S092 这个特例。
   - 用 **条件有效性验证**（`scripts/check_condition_effect.py`）对 config 4 做四项检查，判断条件是否足以引导生成。
2. **阶段 1**：
   - 基线 B0 = 已经训练好的 config 4（[−1,1] 归一化 + S4 dropout 0.03 + `preserve`，没有 EMA）。正在跑的 v2 推荐配置用了 `masked`，只作参考，不作基线。
   - 新基线 B1 = **推荐配置更新**（[−1,1] 归一化 + S4 dropout 0.03 + EMA + `preserve`）+ **学习率调度与梯度裁剪**。和 B0 相比只多了 EMA 和学习率调度，便于看出这两项的效果。
3. **阶段 2**：在 B1 上做两组对照：
   - **模型尺寸可配置**：8 层、128 通道，对比 4 层、64 通道。
   - **学习率调度与梯度裁剪**：开启与关闭的对比。

**判断标准**：主要看 S092 和几个典型受试者上的合并 W1，以及 **条件有效性验证** 的结果是否改善，辅助看 KS、按睡眠阶段的 W1、心率变异性指标和阶梯结构指标。
